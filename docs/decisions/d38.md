# 決策 D38

> **TL;DR**
> - D38 是第 10 施工關開工前提案，把 D32（core 依賴 `serde`）延伸到 `PipelineState` 與 binding 快照兩個型別。
> - 記住：**快照不存 workflow**，workflow 由 task 的 `workflow_id`＋`workflow_version`（D21）從 `workflows` 表讀。
> - 下一步：回 [../DECISIONS.md](../DECISIONS.md) 找其他決策。

每條格式：決定 · 理由 · 否決的方案 · 證據。

## D38

- 決定：D32 的 serde derive 範圍延伸到兩個型別：
  1. `PipelineState` 與它的欄位型別加 serde derive，存成 task 資料列上的快照欄位（第 5 施工關 P4 已定「存快照」）；讀回只經 `PipelineState::restore(快照, ValidatedWorkflow) -> Result` 這一條路，檢查 task id、關卡位置在範圍內、每個關卡都有 attempt、紀錄裡的 stage id 都在 workflow 裡，不合規則的快照不會被接受；快照不含 workflow（workflow 由 task 的 `workflow_id`＋`workflow_version` 讀）。golden JSON 測試鎖格式，只准加欄位（比照 D26），舊快照要讀得回來（每加欄位附一份舊 fixture，比照第 5 施工關 P5）。
  2. binding 快照的型別從 `agend_shim::binding::Snapshot` 搬到 core（第 3 施工關 T1 已建議），路徑改成 `String`（core 是 no_std），shim 與 daemon 共用同一個型別；golden JSON 測試證明格式沒變。
- 理由：重播事件的問題第 5 施工關已經講過；快照加一道 `restore` 檢查，外面仍然造不出不合規則的狀態（P2）。一個型別兩邊用，格式不會漂移（P4）。
- 否決的方案：快照連 workflow 一起存（兩份真相）；不檢查直接 `Deserialize`（等於開放偽造）（P2）。
- 證據：使用者 2026-09-26 確認第 10 施工關 P2、P4（[gate-10-pipeline.md](../gates/gate-10-pipeline.md#p2pipelinestate-快照怎麼防偽造重開機後要重做什麼)、[P4](../gates/gate-10-pipeline.md#p4worktreebindinghookbinding-快照)）。
