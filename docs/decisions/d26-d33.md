## D33

- 決定：
  1. 一個 agent 同時最多持有一個 task，從派工起持有到 done 或取消，包括等待 submit、checks、review 的期間。審查指派就是 reviewer 的那一個 task。取代可設定的每個 instance task concurrency。
  2. 要求修改後的返工一定回到 task 目前的持有者（作者）。作者仍持有這個 task，所以不會有「作者正在忙別的 task」的情況，返工不需要等作者空出來。
  3. 持有者無法繼續時：額度用盡 → 依 D18 改派同角色、另一個允許 backend 的成員，並交接審查意見與目前的 branch；沒有空的成員就在角色人數上限內開臨時 instance；都不行就排隊（原因：額度）。持有者被操作者刪除 → 立即改派同角色成員（或在人數上限內開臨時 instance）。臨時 instance 只在它持有的 task 結束後才回收，所以返工中的作者不會被回收。
  4. 取消「等待 fanout 的父 task 不佔名額」的特例：父 task 的 agent 等待期間照樣持有 epic；子 task 派給其他 agent；team 內互等由既有的互等偵測發現，並通知使用者。
- 理由：一個 agent 一個 task、作者在審查期間仍持有 task，返工就不會遇到作者在忙；剩下的失敗情況只有額度用盡與被刪除。shim 一次只能把一個 agent 導向一個 worktree，一個 agent 同時做兩個 branch task 在結構上本來就做不到。
- 接受的代價：agent 在等 checks／review 時閒置；並行度等於 agent 數，靠角色人數上限（臨時 instance）調整。
- 否決的方案：草稿原本的行為——每個 instance 可設定 task 數、返工遇到作者沒空位就排隊等作者、作者不在就排隊不改派、等待 fanout 的父 task 不佔名額（見 [gate-01-core.md 的 Q1](../gates/gate-01-core.md#q1返工時原作者不能接round-1-review-i8)）。
- 證據：使用者 2026-09-25 決定（第 1 關 round-1 review I8 的待決定事項）。實作與測試：`crates/agend-core/src/policy/assign.rs`。
